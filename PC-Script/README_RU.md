# ESP32 → ПК: два Bluetooth-геймпада и два виртуальных DS4

В комплекте есть ESP-IDF исходник Bluetooth HID host, Python-приложение и
проверки бинарного UART-протокола. Протокол версии 2 передаёт номер слота в
каждом HID-отчёте; слот 1 управляет первым виртуальным DS4, слот 2 — вторым.
Геймпады сопрягаются с ESP32 по очереди, соединение с ПК — по USB/UART.

## Что изменено

- ESP32 хранит два отдельных HID-соединения и снова подключает сохранённые
  Bluetooth-пары после перезапуска.
- Python создаёт до двух виртуальных DualShock 4 через `vgamepad`/ViGEmBus.
- Для каждого слота отдельно выбираются HID-профиль и цвет индикатора.
- По умолчанию интерфейс предлагает зелёный (`#00FF00`) для слота 1 и синий
  (`#0060FF`) для слота 2. Если для подключённой модели загружен профиль
  подсветки, цвет автоматически отправляется при подключении.
- Сырые HID-отчёты записываются в JSONL и включают номер слота.
- UART использует кадры с маркером, длиной и CRC-16/CCITT-FALSE; отладочные
  сообщения прошивки не пишутся в UART0, чтобы не портить бинарный поток.

## Важное ограничение: модель геймпада

Исходные файлы не содержали модели геймпада или проверенного HID-профиля.
Поэтому комплект **не угадывает** смещения осей/кнопок и формат команды
подсветки. Пустой `raw-only.json` позволяет увидеть и записать данные, но сам
по себе не преобразует кнопки в виртуальный DS4 и не включает световую панель.
Загрузите отдельный профиль для каждого слота с точными HID-полями вашей
модели. Для профиля подсветки нужно проверить на реальном геймпаде также
`report_id`, `template_hex` и смещения RGB.

Чтобы составить профиль, подключите один контроллер, включите запись HID-отчётов
в приложении, по очереди нажмите кнопки и переместите стики, затем сохраните
JSONL. Для точного профиля нужны модель/ревизия обоих контроллеров и эта
запись (желательно также HID report descriptor, если он доступен).

## Запуск Python на Windows

1. Установите ViGEmBus (не входит в Python-пакет).
2. Установите Python 3.10+ и подключите ESP32 по USB.
3. Запустите `run_windows.bat`. Скрипт создаст `.venv`, установит зависимости
   и откроет GUI.
4. Выберите COM-порт ESP32 и нажмите «Подключить».
5. Нажмите «Начать поиск и сопряжение», переведите первый геймпад в режим
   Bluetooth-сопряжения, затем повторите для второго. ESP32 удерживает поиск
   включённым, пока есть свободный слот. Для повторного подключения
   сопряжённых устройств пары сохраняются во flash/NVS.
6. Загрузите правильный профиль отдельно для каждого слота. Пока профиля нет,
   приложение покажет два виртуальных устройства, но их кнопки останутся
   нейтральными.

Для цвета выберите слот в панели «Команды геймпаду», задайте цвет и нажмите
«Отправить цвет». Формат HID-output зависит от модели и должен быть в профиле.

## Сборка прошивки

`firmware/main/main.c` рассчитан на ESP-IDF с поддержкой Bluedroid Classic
Bluetooth и ESP HID Host. В `firmware/` находится минимальная структура
проекта; перед сборкой задайте корректную цель платы через `idf.py set-target`.
Проверьте, что в конфигурации включён Classic Bluetooth и разрешены как минимум
два BR/EDR ACL-соединения. На ESP32-S2/S3/C3 нет Bluetooth Classic, поэтому
этот вариант прошивки для них не подходит.

Плата должна иметь доступный USB-UART на UART0. Скорость протокола — 921600,
8N1, без аппаратного flow control. Не запускайте одновременно Serial Monitor
и Python-приложение на том же COM-порту.

## Проверки

Из каталога комплекта:

```text
python -m unittest discover -s tests -v
python -m compileall -q .
```

Python-проверки тестируют кадрирование, CRC, статус двух слотов и структуру
HID-input. Проверка прошивки на настоящей плате требует выбранной ESP-IDF
версии и целевого чипа; приложенные файлы не содержали этих сведений.
